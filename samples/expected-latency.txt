# 延迟与内存的验收口径（键 = 值；时间单位秒 / 毫秒，内存单位 MB，体积单位字节）
# 被测规模
词表规模 = 100000 条（samples/words/big.txt，约 1.7 MB）
查询清单 = samples/queries/big.txt 的全部 12 条查询
运行环境 = 单进程、单并发、索引已落盘；接口延迟只算本机回环，不含网络

# 构建阶段
构建耗时上限 = 8 s（外部计时，wall time，含词表解析与索引落盘）
构建峰值内存上限 = 512 MB（RSS 峰值）
索引体积上限 = 词表文件字节数的 3 倍（含 manifest.json 与全部数据文件）
构建确定性 = 同一词表重复构建，查询结果必须一致（不要求索引字节一致）

# 查询阶段
冷启动单次查询上限 = 1.5 s（进程启动 + 载入索引 + 一次查询）
热查询 p50 上限 = 5 ms（同一进程、索引已加载）
热查询 p95 上限 = 20 ms
热查询 p99 上限 = 40 ms
热查询统计方式 = 每条查询分别统计后取分位，不把不同查询混在一起
空前缀 = 计入热查询统计，与其它前缀同一阈值；清空搜索框不得触发全表扫描
查询峰值内存上限 = 512 MB（RSS 峰值）
接口端到端 p95 上限 = 50 ms（GET /api/complete，本机回环，单并发，不重启进程）

# 测量方式
构建计时 = 外部计时命令包住 build 子命令
查询计时 = python cli.py bench --index var/index-big --queries samples/queries/big.txt --repeat 200
索引迁移 = 索引目录复制到别处后仍可查询；查询期间把词表改名或移走，查询必须成功
判定 = 任一指标超标即不通过；正确性（stdout 与期望结果逐字节一致）优先于性能
